# 2026-10-17

## singbox_mt 仓库：新增四个一键部署脚本

在已有 `singbox_mt.sh`（MTPROXY）的基础上，按同一套骨架新增并推送到 `ppopcn/singbox_mt`（main）：

- `singbox_ssr.sh` — Shadowsocks `aes-256-gcm`，默认 8388 tcp+udp，输出 SIP002 `ss://`
- `singbox_hy2.sh` — Hysteria2，默认 443/udp，自签证书 + 可选 salamander 混淆
- `singbox_tuic.sh` — TUIC v5，默认 443/udp，BBR，uuid+password
- `singbox_vless_vmess.sh` — VLESS 8989 + VMess 8990（TLS+WS，路径 /vless、/vmess）

统一骨架：架构识别 → 从 `shtorm-7/sing-box-extended` 下载预编译包并校验 SHA256 → 生成凭据/自签证书 → 写 `/etc/sing-box/*.json`（600）→ `sing-box check` → 注册 `singbox-*` systemd 单元 → 放行 ufw/firewalld → 输出客户端链接；均支持 `info` / `uninstall` / `help`。多脚本共用同一二进制，卸载时只在无其他 `singbox-*.service` 时才删二进制。

### 关键坑（已验证）

- sing-box **没有 SSR 协议**，`aes-256-gcm` 是 Shadowsocks AEAD，客户端要选 Shadowsocks 而不是 ShadowsocksR。
- sing-box 每个端口只能挂一个协议入站，VLESS+VMess 只能分端口（8989/8990）；单端口需前置 nginx/caddy 按 WS 路径分流。
- 1.14 的 Shadowsocks 入站 `network` 必须写成数组 `["tcp","udp"]`，写 `"tcp,udp"` 会报 `unknown network`。
- 1.14 的 VMess 用户字段已不接受 `security`（报 `unknown field "security"`），`alterId` 也不再需要。
- 已用官方 `sing-box 1.14.1-extended-2.7.2` 的 windows-amd64 二进制对所有配置跑 `sing-box check`，四份全部通过。
- Windows/Git Bash 下 `python3 print` 与 `base64` 会带 `\r`：解析 JSON 与生成 vmess base64 链接时必须 `tr -d '\r'`，否则链接里混入 0D。
- `json_get` 在取不到值时返回非 0，在 `set -e` + `VAR="$(json_get ...)"` 下会静默退出 → 函数末尾显式 `return 0`。
- 新增 `.gitattributes`（`*.sh text eol=lf`），本机 `core.autocrlf=true`，否则仓库里的脚本会变成 CRLF 导致 `curl | bash` 挂掉。
